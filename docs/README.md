# OctoAcme Project Management Docs

This folder contains the operating guidance for OctoAcme projects. It brings together the core practices for initiating work, planning delivery, managing risk and communication, tracking execution, releasing changes, and improving the team over time.

## Project management processes

OctoAcme uses a practical, iterative lifecycle to move from idea to delivery. Teams start with project initiation to validate the problem, stakeholders, success metrics, risks, and resource needs. Approved work then moves into planning, where priorities, milestones, estimates, dependencies, and acceptance criteria are defined. During execution, the team tracks progress using a project board, holds standups and sprint reviews, and works through blockers with clear accountability.

The project model is built around clear roles and shared expectations. Project Managers coordinate delivery, communication, and risk management; Product Managers define outcomes and prioritization; developers build and validate the solution; QA validates acceptance criteria and quality; and stakeholders provide input, approvals, and business context. Communication is structured through regular status updates, standups, delivery syncs, demos, and escalation paths when issues require broader attention.

Quality is treated as part of delivery rather than a final step. Teams set acceptance criteria, use pull requests for review, run automated tests and linting, perform relevant unit and integration checks, and complete smoke tests and manual QA where needed. Before a release, work must meet the Definition of Done, CI and security checks, and any deployment and rollback requirements. Retrospectives close the loop by capturing lessons learned and converting them into targeted improvements.
